## Description

As a **platform admin**, I want **scan and M365 connection write operations** restricted to **auditor** and **admin** roles, so **viewers** cannot create scans, change tenant credentials, or delete compliance data without proper authorization.

### Background

Role-based access control is partially implemented:

- Roles: `admin`, `auditor`, `viewer` (`backend-api/app/models/user.py`)
- Dependencies: `require_auditor_or_above`, `require_admin` (`backend-api/app/core/permissions.py`)
- Demo routes: `/v1/test/protected-auditor`, `/v1/test/protected-admin` (`backend-api/app/api/v1/test.py`)
- **Gap:** `scans.py` and `m365_connections.py` use only `get_current_user` on mutation endpoints

### Scope

**In scope**

- Enforce `require_auditor_or_above` on write/mutate endpoints for scans and M365 connections
- Keep read (`GET`) endpoints on `get_current_user` so viewers can still list and view their data

**Out of scope**

- New admin user-management API
- Frontend button/route hiding by role (can follow in a separate UI story)
- Contact admin routes (already use `require_admin`)
- Evidence, benchmarks, settings, platforms (unchanged in this story)

---

## Acceptance criteria

1. **Scans — create:** `POST /v1/scans` returns **403 Forbidden** when the authenticated user has role `viewer`; returns **201** for `auditor` and `admin` (existing behaviour otherwise unchanged).
2. **Scans — delete:** `DELETE /v1/scans/{scan_id}` returns **403** for `viewer`; **204** for `auditor`/`admin` when the scan belongs to the user.
3. **M365 connections — create:** `POST /v1/m365-connections` returns **403** for `viewer`; **201** for `auditor`/`admin`.
4. **M365 connections — update:** `PUT /v1/m365-connections/{connection_id}` returns **403** for `viewer`; **200** for `auditor`/`admin` when the connection belongs to the user.
5. **M365 connections — delete:** `DELETE /v1/m365-connections/{connection_id}` returns **403** for `viewer`; **204** for `auditor`/`admin` when the connection belongs to the user.
6. **M365 connections — test:** `POST /v1/m365-connections/{connection_id}/test` returns **403** for `viewer`; succeeds for `auditor`/`admin`.
7. **Read access unchanged:** All `GET` endpoints on scans and M365 connections remain available to any authenticated user (`viewer`, `auditor`, `admin`) with existing ownership checks.
8. **Error shape:** 403 responses use the same detail pattern as existing permission dependencies (e.g. `"Auditor or Admin access required"`).
9. **Documentation:** PR description references this story ID and lists endpoints changed.

## Technical notes

### Endpoints to protect

Use `current_user: User = Depends(require_auditor_or_above)` instead of `Depends(get_current_user)` on:

**`backend-api/app/api/v1/scans.py`**

| Method | Path | Action |
|--------|------|--------|
| POST | `/` | create_scan |
| DELETE | `/{scan_id}` | delete_scan |

**Leave on `get_current_user`:** `GET /`, `GET /readiness`, `GET /{scan_id}`, `GET /{scan_id}/summary`, `GET /{scan_id}/results`

**`backend-api/app/api/v1/m365_connections.py`**

| Method | Path | Action |
|--------|------|--------|
| POST | `/` | create_connection |
| PUT | `/{connection_id}` | update_connection |
| DELETE | `/{connection_id}` | delete_connection |
| POST | `/{connection_id}/test` | test_connection |

**Leave on `get_current_user`:** `GET /`, `GET /{connection_id}`

### Implementation pattern

Follow the existing demo in `test.py`:

```python
from app.core.permissions import require_auditor_or_above

@router.post("/")
async def create_scan(
    ...,
    current_user: User = Depends(require_auditor_or_above),
):
```

Import `require_auditor_or_above` in each route file; no changes needed to `permissions.py` unless you want a shared alias for clarity.

### Optional follow-up (not required for this story)

- Frontend: disable Create Scan / Add Connection buttons for `viewer` role
- API tests: pytest coverage for 403 cases (backend has no test suite yet)

## Testing notes

### Manual (minimum)

1. Log in as **admin** (`admin@example.com` / `admin` in dev) — confirm create scan, create connection, delete still work.
2. Create or use a **viewer** test user (register + set `role = 'viewer'` in DB, or add a dev seed user).
3. With viewer JWT, call mutation endpoints (Swagger at http://localhost:8000/docs or frontend):
   - Expect **403** on POST/PUT/DELETE/test
   - Expect **200** on GET list/detail
4. Repeat one mutation as **auditor** if available — expect success.

### Automated (implemented)

Run from `backend-api/`:

```bash
uv sync --extra dev
uv run pytest tests/ -v
```

**Coverage (12 tests):**

- Scans: viewer 403 on POST/DELETE; viewer 200 on GET list; viewer 404 (not 403) on GET detail; admin passes RBAC on POST
- M365 connections: viewer 403 on POST/PUT/DELETE/test; viewer 200 on GET list; viewer 404 on GET detail; admin passes RBAC on PUT
- All viewer 403 responses use detail: `"Auditor or Admin access required"`
